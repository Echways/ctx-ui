# ctx-ui

[English](../../README.md) · **Русский**

Шлюз и веб-панель для раздачи доступа к MCP-серверам по образцу 3x-ui.
Inbound — адрес (`/mcp/<slug>`), за которым стоит удалённый MCP-сервер.
Клиент — токен со сроком, набором inbound'ов и лимитами.

Есть HTTP-inbound'ы (streamable HTTP), лимиты и квоты клиентов, журнал
вызовов, веб-панель, CLI и REST API со Swagger UI.

## Установка

Бинарник + systemd, Linux x86_64/aarch64:

```bash
curl -fsSL https://github.com/Echways/ctx-ui/releases/latest/download/install.sh | sudo bash
```

Обновление до последнего релиза: `sudo ctx-ui update`. Остановить сервис:
`sudo ctx-ui down`, запустить снова: `sudo ctx-ui up`. Удалить всё, вместе с
настройками и данными: `sudo ctx-ui uninstall`.

Docker + Caddy, удаление, резервная копия: [install.md](install.md).
TLS сервис не терминирует; перед ним ставится Caddy или nginx.

## Быстрый старт

```bash
sudo ctx-ui admin add admin
sudo ctx-ui inbound add learn --url https://learn.microsoft.com/api/mcp
sudo ctx-ui client add "Иванов 4419" --inbound learn --expires 2027-07-01
```

`admin add` печатает логин, одноразово показанный пароль и секретный адрес
панели. `client add` печатает токен и адреса подключения. В Docker команды
идут через `docker compose exec ctx-ui`.

Вывод программы, ошибки шлюза и API по умолчанию на английском. Для русского
задайте `CtxUi__Language=ru`; подробнее — в
[configuration.md](configuration.md#язык).

## Подключение клиента

| Способ | Адрес |
| --- | --- |
| заголовок `Authorization: Bearer <токен>` | `https://<хост>/mcp/<slug>` |
| токен в пути, для клиентов без своих заголовков | `https://<хост>/k/<токен>/mcp/<slug>` |

```bash
claude mcp add --transport http learn https://mcp.example.com/mcp/learn \
    --header "Authorization: Bearer tnk_..."
```

Адрес с токеном равносилен паролю.

## Вход через браузер (OAuth)

Приложения вроде Claude, ChatGPT и Cursor подключаются по одному адресу
сервера и входят в браузере, без копирования ключа. По умолчанию **выключен**:
пока он выключен, ничего не меняется, а `/.well-known/*` и `/connect/*`
отвечают 404. Включается командой `ctx-ui oauth on` или в панели; нужен
публичный адрес с `https://`.

| Способ входа | Что делает человек |
| --- | --- |
| ключ клиента | один раз вставляет его на странице входа |
| Google, GitHub, GitLab, Microsoft, Яндекс, VK ID, Discord, Telegram или любой провайдер OpenID Connect | входит аккаунтом, который администратор привязал одноразовой ссылкой-приглашением |

Каждый браузер — устройство; у клиента может быть лимит устройств, а
администратор в любой момент отключает устройства. Подробности, провайдеры и
что делать, если вход не открывается: [docs/ru/oauth.md](oauth.md).

## Панель

Доступна только по случайному пути из 16 символов; на любой другой путь —
404. Говорит на языке из `CtxUi__Language`, пока администратор не выбрал
свой; кнопка в верхней панели (и ссылка под формой входа) переключает
английский и русский, выбор хранится в cookie год.

| Раздел | Содержимое |
| --- | --- |
| Обзор | активные клиенты, вызовы и сбои upstream за сутки; итоги по inbound'ам и по дням |
| Inbounds | создание, правка, включение/выключение, удаление |
| Клиенты | создание, правка, включение/выключение, поиск, окно «Подключение», новый токен, сброс квоты |
| Журнал | последние вызовы, фильтр по клиенту |
| Ключи API | выпуск, отзыв, ссылка на Swagger UI |
| OAuth | переключатель входа через браузер, провайдеры, значения по умолчанию для устройств |

Изменения применяются в шлюзе сразу. Окно «Подключение» показывает токен,
адреса и готовое сообщение для клиента.

Таймаут запроса (по умолчанию 300 с, 1–3600) и предел тела запроса (по
умолчанию 4 МБ, 1 КБ–64 МБ) inbound'а задаются только в панели.

Вход: пароль генерируется (20 символов), показывается один раз, хранится
хешем. 5 неверных попыток закрывают логин на 15 минут. Cookie сеанса живёт
7 дней со скользящим продлением.

## CLI

Изменения из CLI доходят до запущенного сервиса за `RefreshInterval`
(1 с). Перезапуск не нужен.

### admin

| Команда | Действие |
| --- | --- |
| `admin add <логин>` | создать администратора; печатает пароль и адрес панели |
| `admin password <логин>` | новый пароль; закрывает сеансы, снимает блокировку |
| `admin list` | список с состоянием блокировки |
| `admin remove <логин>` | удалить |
| `admin path [--new]` | адрес панели; `--new` выдаёт новый, действует после перезапуска |

Логин: 1–64 символа, `A-Z a-z 0-9 . _ -`.

### inbound

| Команда | Действие |
| --- | --- |
| `inbound add <slug> --url <адрес>` | inbound на MCP-сервер со streamable HTTP |
| `inbound list` | slug, состояние, адрес |
| `inbound enable\|disable <slug>` | включить/выключить без удаления |
| `inbound remove <slug>` | удалить и отозвать у всех клиентов |

Параметры `add`: `--name <текст>` название в списке (по умолчанию slug);
`--header Имя=значение` заголовок для upstream, повторяемый, хранится
зашифрованным; `--forward-identity` передавать upstream заголовки личности
клиента.

Slug: 1–64 символа, `a-z 0-9 -`, без дефиса по краям.

### client

| Команда | Действие |
| --- | --- |
| `client add <имя> --inbound <slug>` | выпустить клиента; печатает токен и адреса |
| `client show <имя>` | токен, адреса, лимиты, расход квоты |
| `client set <имя>` | изменить срок, inbound'ы, лимиты |
| `client reset <имя>` | обнулить счётчик квоты, начать период заново |
| `client reissue <имя>` | новый токен; старый перестаёт работать |
| `client list` | имя, состояние, срок, последнее обращение, квота, inbound'ы |
| `client devices <имя>` | устройства: приложения, способ входа, последнее использование, IP, состояние |
| `client device-off <имя> <id>\|--all` | отключить устройство (id или его начало) или все |
| `client invite <имя>` | одноразовая ссылка для привязки чужого аккаунта; действует 7 дней |
| `client links <имя>` | аккаунты, привязанные к клиенту |
| `client unlink <имя> <провайдер>` | снять привязки провайдера |
| `client enable\|disable <имя>` | включить/выключить без удаления |
| `client remove <имя>` | удалить |

Параметры `add` и `set`:

| Параметр | Значение |
| --- | --- |
| `--inbound <slug>` | повторяемый; в `set` заменяет весь набор |
| `--expires ГГГГ-ММ-ДД` | доступ закрывается в 00:00 UTC этого дня; `never` в `set` снимает срок |
| `--meta ключ=значение` | только `add`; повторяемый; уходит как `X-Mcp-Meta-<ключ>` |
| `--rate N` | запросов в минуту |
| `--concurrency N` | одновременных `POST` |
| `--quota N` | `tools/call` за период |
| `--reset-days N` | длина периода квоты; без него квота разовая |
| `--devices N` | лимит устройств при входе через браузер; `none` в `set` снимает его |
| `--direct-key on\|off` | работает ли ключ в заголовке и адресе или только для входа |

В `set` значение `none` снимает лимит. Не указанные параметры не меняются.

Имя: 1–100 символов, уникально без учёта регистра, без управляющих
символов. Имя с пробелами берётся в кавычки.

### usage

| Команда | Действие |
| --- | --- |
| `usage days [--days N]` | итоги по дням за N последних дней (по умолчанию 7, максимум 3650) |
| `usage log [--limit N]` | последние вызовы, новые сверху (по умолчанию 50, максимум 1000) |

Обе принимают `--client <имя>`. Время в UTC. Данные попадают в базу раз в
`FlushInterval` (5 с), поэтому видны с небольшой задержкой.

### oauth

| Команда | Действие |
| --- | --- |
| `oauth status` | состояние, адрес метаданных сервера, значения по умолчанию, провайдеры и их адреса возврата; предупреждает, если OAuth невозможен из-за публичного адреса |
| `oauth on\|off` | включить или выключить вход через браузер; `off` предупреждает о клиентах без постоянного ключа |
| `oauth key on\|off` | разрешить или запретить вход по ключу |
| `oauth set [--idle-days N] [--self-revoke on\|off] [--devices N\|none] [--direct-key on\|off]` | срок неактивности устройств, самостоятельное отключение, значения по умолчанию для новых клиентов |
| `oauth provider set <имя> --client-id <id>` | добавить провайдера или изменить его |
| `oauth provider on\|off\|remove <имя>` | включить, выключить, удалить |
| `oauth provider list` | настроенные провайдеры |

`provider set` берёт секрет из `--client-secret`, со стандартного ввода при
`--client-secret-stdin` или из `CTX_UI_PROVIDER_SECRET`; для oidc добавьте
`--issuer <https://…>` и `--title <текст>`. Имена: `google`, `microsoft`,
`github`, `gitlab`, `yandex`, `vkid`, `discord`, `telegram`, `oidc`.

### apikey

| Команда | Действие |
| --- | --- |
| `apikey add <название>` | выпустить ключ REST API; печатает его один раз вместе с адресами API и Swagger |
| `apikey list` | название, начало ключа, дата выпуска |
| `apikey remove <название>` | отозвать; запросы с ключом сразу получают 401 |

Название: 1–64 символа, `A-Z a-z 0-9 . _ -`.

## REST API

Живёт под секретным путём панели, как и она сама:

| Адрес | Что это |
| --- | --- |
| `https://<хост>/<секрет>/api/v1/…` | API, ключ в `Authorization: Bearer ctxk_…` |
| `https://<хост>/<секрет>/swagger/` | Swagger UI, ключ вводится в «Authorize» |
| `https://<хост>/<секрет>/openapi/v1.json` | документ OpenAPI 3.1 |

| Ресурс | Методы |
| --- | --- |
| `inbounds`, `inbounds/{slug}` | список, один, `PUT` создаёт или заменяет, `enable`, `disable`, `DELETE` |
| `clients`, `clients/{id}` | список (`?name=` находит одного), один, `POST` выпускает, `PATCH` меняет, `connection`, `enable`, `disable`, `reset-quota`, `reissue`, `DELETE` |
| `clients/{id}/devices`, `…/devices/{deviceId}` | список устройств, `DELETE` отключает одно или все |
| `clients/{id}/invite`, `clients/{id}/links`, `…/links/{linkId}`, `…/links/{provider}` | `POST` выпускает ссылку-приглашение, список привязок, `DELETE` отвязывает один аккаунт или все аккаунты провайдера |
| `oauth`, `oauth/providers/{name}` | настройки (`PATCH`), провайдеры (`PUT`, `enable`, `disable`, `DELETE`); секреты не возвращаются никогда |
| `usage/days`, `usage/log`, `overview` | итоги по дням, последние вызовы, «Обзор» панели |

Ошибки приходят как `application/problem+json`: 400 неверные данные, 401 нет
ключа или он неизвестен, 404 нет такого объекта, 409 токен показать нельзя
(потерян `keys/`). Текст `detail` тот же, что печатает CLI. Изменения
доходят до шлюза сразу.

```bash
curl -H "Authorization: Bearer ctxk_..." https://mcp.example.com/<секрет>/api/v1/clients
```

Сеанс панели API не открывает: браузер прикладывает cookie к запросам с
любого сайта.

## Лимиты

Каждый лимит необязателен; не заданный не действует.

| Лимит | Что считает | При превышении |
| --- | --- | --- |
| `--rate` | все запросы, token bucket | HTTP 429, `Retry-After: <секунд до следующего>` |
| `--concurrency` | одновременные `POST` | HTTP 429, если слот не освободился за 1 с, `Retry-After: 1` |
| `--quota` | `tools/call` за период | HTTP 200, результат tool с `isError: true` и временем сброса |

Квоту расходует только `tools/call`. С исчерпанной квотой клиент
по-прежнему подключается и видит список tools; отказ приходит результатом
tool, и модель пересказывает его человеку. Вызовы, на которые upstream
ответил HTTP ≥ 400 или не ответил, возвращаются в квоту.

```bash
sudo ctx-ui client set "Иванов 4419" --quota 500 --reset-days 30 --rate 60
sudo ctx-ui client set "Иванов 4419" --rate none
```

## Ответы шлюза

| Статус | `error` | Причина |
| --- | --- | --- |
| 401 | `token_missing` | нет токена |
| 401 | `token_unknown` | токен не найден |
| 401 | `client_disabled` | клиент отключён |
| 401 | `client_expired` | срок истёк |
| 404 | `inbound_not_found` | inbound'а нет, он выключен или не выдан клиенту |
| 429 | `rate_limited`, `too_many_concurrent` | превышен лимит |
| 413 | `body_too_large` | тело больше предела inbound'а |
| 400 | JSON-RPC `-32600` | тело не JSON-RPC или пакет больше 100 сообщений |

## Что получает upstream

Запрос клиента без токена плюс заголовки inbound'а. С `--forward-identity`:
`X-Mcp-Client-Id`, `X-Mcp-Client-Name`, `X-Mcp-Meta-<ключ>`, значения в
UTF-8 с процентным кодированием. Такие же заголовки от клиента вырезаются.
