# Вход через браузер (OAuth)

[English](../oauth.md) · **Русский**

По умолчанию выключен. Пока он выключен, `/.well-known/*` и `/connect/*`
отвечают пустым 404, а всё остальное работает как прежде.

Включить можно командой `ctx-ui oauth on` или в разделе **OAuth** панели.
Нужен `CtxUi__PublicUrl`, начинающийся с `https://` (для разработки подходит
`http://localhost`).

## Как это выглядит для человека

1. Человек добавляет в приложение (Claude, ChatGPT, Cursor и другие) адрес
   сервера `https://<host>/mcp/<slug>`. Ключ копировать не нужно.
2. Приложение само находит страницу входа и открывает её в браузере.
3. Человек входит ключом клиента или, если администратор привязал аккаунт,
   через Google, GitHub и другие.
4. Браузер один раз спрашивает, можно ли приложению пользоваться сервером, и
   возвращается в приложение. Дальше оно работает и само продлевает доступ.

Адрес тот же, что и для прямого ключа, поэтому клиент может подключаться
любым способом.

## Устройства и лимит

Браузер, в котором вошли, — это **устройство**; его помнит cookie, год.
Второе приложение, открытое в том же браузере, — то же устройство, входить
заново не нужно.

- У клиента может быть лимит устройств (`--devices N`, поле в окне клиента,
  значение по умолчанию в разделе OAuth). Сверх лимита страница входа
  показывает устройства и предлагает заменить одно, если администратор не
  запретил.
- Устройство, которым не пользовались весь срок неактивности (по умолчанию 30
  дней, 1–365), отключается. Refresh-токен живёт столько же и сдвигается при
  каждом использовании.
- Администратор отключает устройства в панели («Устройства» в меню клиента),
  командой `ctx-ui client device-off` или через API. Приложение получит отказ
  при следующем вызове.
- Повторное использование refresh-токена (позже чем через 30 секунд) значит,
  что копия утекла: устройство отключается.
- `--direct-key off` оставляет ключ клиента только для входа: в заголовок или
  адрес его уже не подставить.

## Приглашения

Чужой аккаунт привязывается к клиенту только по одноразовой ссылке, поэтому
посторонний, вошедший через Google, ничего не получит.

```bash
sudo ctx-ui client invite "Иванов 4419"
```

Ссылка `https://<host>/connect/invite/<код>` срабатывает один раз и живёт 7
дней. Её выпускают панель (окно «Подключение»), REST API
(`POST /clients/{id}/invite`) и CLI. `client links` и `client unlink` показывают
и снимают привязки.

## Провайдеры

Каждому провайдеру нужно приложение, созданное в его консоли, и адрес возврата
`https://<host>/connect/callback/<имя>`. Настроить провайдера можно в панели,
командой `ctx-ui oauth provider set <имя> --client-id <id> --client-secret-stdin`
или через API. Изменение применяется сразу, без перезапуска.

| Имя | Где создать приложение | Права (scopes) |
| --- | --- | --- |
| `google` | Google Cloud console → APIs & Services → Credentials → OAuth client ID, тип «Web application» | `openid profile email` |
| `microsoft` | Microsoft Entra → App registrations, платформа «Web» | `User.Read` |
| `github` | GitHub → Settings → Developer settings → OAuth Apps | ничего сверх умолчания |
| `gitlab` | GitLab → Preferences → Applications | `read_user` |
| `yandex` | oauth.yandex.ru, платформа «Веб-сервисы» | логин и почта |
| `vkid` | VK ID для бизнеса, платформа «Web» | по умолчанию (имя) |
| `discord` | портал разработчиков Discord → OAuth2 | `identify` |
| `telegram` | @BotFather → «Вход через Telegram» (OpenID Connect) | `openid profile` |
| `oidc` | любой провайдер OpenID Connect (Keycloak, Authentik, Okta…); нужны адрес issuer с `https://` и название | `openid profile email` |

Секрет хранится зашифрованным и больше не показывается. В панели пустое поле
секрета оставляет прежний.

## Совместимость

Сервер следует правилам авторизации MCP: метаданные защищённого ресурса по
адресу `/.well-known/oauth-protected-resource/mcp/<slug>`, метаданные сервера
авторизации по адресу `/.well-known/oauth-authorization-server`, динамическая
регистрация клиентов, документы метаданных клиента (client ID metadata), PKCE
(только `S256`) и параметр `resource`. Так подключаются Claude Code, claude.ai
(свой коннектор), ChatGPT (коннектор) и Cursor (`url` в `mcp.json`).

```bash
claude mcp add --transport http learn https://mcp.example.com/mcp/learn
```

## Если вход не открывается

- `CtxUi__PublicUrl` должен быть тем адресом, по которому ходит браузер, и
  начинаться с `https://`. Если OAuth включён, а адрес другой, при запуске в
  журнале появится предупреждение.
- `curl https://<host>/.well-known/oauth-authorization-server` должен вернуть
  JSON, где `issuer` — этот адрес. Пустой 404 означает, что OAuth выключен.
- За прокси задайте `CtxUi__TrustedProxies` (см.
  [configuration.md](configuration.md)), иначе у всех устройств в записи будет
  адрес прокси. Прокси должен передавать `X-Forwarded-For` и
  `X-Forwarded-Proto`.
- `ctx-ui oauth status` печатает состояние и адрес возврата каждого
  провайдера.
